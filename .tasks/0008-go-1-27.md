# Move to Go 1.27

## Goal

Build, test and release with Go 1.27, the current stable release (1.27.3 as of
2026-11-06). go.mod still says `go 1.26`.

## State (2026-11-06)

- `go.mod` says `go 1.26` and has no `toolchain` line. Every workflow reads its
  Go version from `go.mod` (`go-version-file: go.mod`), so CI uses the newest
  1.26.x.
- CONTRIBUTING.md says "Go 1.26+".
- `make check-go-staticcheck` fails under a Go 1.27 toolchain (the devcontainer
  has go1.27.3) with "export data version 5 is greater than maximum supported
  version 2". The pinned `honnef.co/go/tools v0.7.0` predates Go 1.27.
  staticcheck 2026.2.2 (`v0.8.2`, 2026-10-12) is the current release.

## Plan

1. Bump the `go` directive to `go 1.27` (`go mod edit -go=1.27`, then
   `go mod tidy`). Decide whether to add a `toolchain go1.27.x` line. The
   workflows read the version from go.mod, so the directive alone already moves
   CI to the newest 1.27.x.
2. Bump the staticcheck tool to `honnef.co/go/tools@v0.8.2`, which supports
   Go 1.27 (`go get -tool honnef.co/go/tools/cmd/staticcheck@v0.8.2`). That
   may also move `golang.org/x/tools`.
3. Use the new language and library features only where they make code
   simpler. Run `go fix ./...` and review what it proposes. Do not rewrite code
   just because a newer form exists.
4. Update CONTRIBUTING.md's prerequisite ("Go 1.26+").
5. Verify: `make check` (gofmt, vet, staticcheck), `make test-go` with
   `-race`, and the e2e jobs. The Tier-1 and Tier-2 GNOME jobs build with
   `CGO_ENABLED=0`. Also run one release build for amd64 and arm64.
6. The AUR package builds with Arch's `go` package. Check that Arch ships 1.27
   before the first release that needs it.
